## OpenCode 现场补验

- 从 Release 回下载安装包，校验安装包与内嵌 EXE 的 SHA256，直接运行内嵌的 `plate-workbench.exe`。OpenCode 使用隔离配置和模型 `deepseek/deepseek-flash`，API Key 通过临时进程环境传入，配置只记录 API 地址和模型。
- `TODO(@opencode)` 的四行中文指令由编辑器交办按钮交给插件。整数只写在合成来源笔记中。派发后图谱激活了这条笔记，回执给出 `953`、原样标记及该笔记的 UUID。采纳按钮触发后，直接读取 SQLite 与磁盘 Markdown 核对状态和逐行内容。[待审阅截图](evidence/field-s9.2/opencode/pending.png) · [已采纳截图](evidence/field-s9.2/opencode/adopted.png)
- 首次自动化点击遇到按钮 DOM 重建，在派发前超时。复跑在按钮可见后触发编辑器的点击事件，覆盖交办与采纳的处理链路。截图可见窄抽屉中的任务正文横向溢出，采纳后的三行引用在富文本预览中合并显示。磁盘上的 Markdown 三行引用逐行保留。
- 复跑入口为 `node tauri-migration/evidence/s9-field-e2e.mjs opencode <S9.2 内嵌 EXE> <证据目录> <npm 生成的 opencode.cmd>`。先在独立临时目录安装 `opencode-ai@1.19.6` 和 `playwright`，使 Node 能从源码依赖或 `NODE_PATH` 解析 Playwright。将密钥文件路径传给 `PLATE_S9_FIELD_DEEPSEEK_KEY_FILE`。测试只提交合成数据。[验收脚本](evidence/s9-field-e2e.mjs)
