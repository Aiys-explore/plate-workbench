# Plate S9.6 Windows 验收

2026-11-19 在已有 WebView2 的 Windows x64 主机上验收。

## 首次启动和重启

- 用与正式版同源码、独立应用标识和独立安装名的 S9.6 NSIS 候选实装。系统「文档」下原先没有 `Plate Workbench`，候选启动后显示该位置，点击「打开笔记」前目录和数据库均未创建。
- 点击「打开笔记」后读取 `文档\Plate Workbench\index.sqlite`，确认写入了默认项目，并核对本机 `workspace.json` 中的登记路径。完全退出进程后重启，直接进入同一工作区。
- 带中文、日文、韩文及空格的自选目录可以建库并重启恢复。将登记指向不存在的目录后，Plate 提示重新选择，原数据库仍在。临时默认库已清理，隔离候选已卸载。
- 正式安装器解出的主程序通过 16 项合成回归，覆盖旧库读取、交办与采纳、演化历史和图谱动效。

## GitHub 更新和交付

- `fundops-notes/plate-workbench` 为公开仓库。Plate 在「帮助 → 版本与安装」读取公开的 S9 更新清单，由使用者点击安装。Tauri 拒绝签名不匹配、或签名版本与清单不符的安装包。
- 已在正式安装载荷实测 S9.6 读取 GitHub 清单并显示「当前已是最新版本」。匿名下载 Release 安装包后，SHA256 和清单中的签名与本地发布包一致。
- 用版本设为 `0.5.0-s9.5.1` 的隔离候选实测检测到 S9.6。Tauri 下载完整的 5,429,257 字节，并通过签名和签名版本校验。测试在启动覆盖安装前结束。
- `checkpoint/tauri-s9` 的构建源码提交 `c36ea18628b20f28d5202225ba77742257134020` 已核对远端，发布标签 `v0.5.0-s9.6` 指向同一 SHA。远端更新清单提交 `4788ee10103f2f230cd921fee2f020fb9dfe1db8`。
- Windows x64 安装包 5,429,257 字节。SHA256 为 `D966002B545BD69B94A71866744FD7019AF9BC4852DFE15E5A908201185B09B9`。安装器内嵌 EXE 的 SHA256 为 `8A0471A8927D7EFB39F131CED0E1B6F5846BFBF80BE4C786EB4E4DFA6455361C`。[S9.6 Release](https://github.com/fundops-notes/plate-workbench/releases/tag/v0.5.0-s9.6)

## 后续发布

S9.5 或更早的客户端需先运行 S9.6 安装器。发布后续版本时提升版本号，用同一把更新签名密钥构建 NSIS 安装包及 `.sig`，发布 GitHub Release 后更新 `updates/windows-x64.json` 中的版本、发布日期、资产地址和签名。签名私钥加密保存在发布机的 Windows 用户应用数据区，公开仓库中仅有验证公钥及发布签名。

正式安装的跨版本覆盖升级、干净 Windows 首装及 WebView2 首次部署待验。多语言路径测试使用本机合成目录，其他显示语言及文档重定向环境待现场验收。
