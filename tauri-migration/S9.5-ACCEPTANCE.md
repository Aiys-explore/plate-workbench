## 记忆提案的实际流程

1. Agent 可在回复末尾附带结构化 `<brain-delta>`。待审阅的回执将正文明文和结构化提案分开展示，可以先点「预览记忆提案」查看。
2. 点「采纳」将回执正文按 Markdown 引用写入任务所在笔记，并把任务标为 `DONE`。提案此时仍待应用，关联笔记和事实断言保持原状。
3. 从已采纳回执打开「记忆提案」，再点「应用记忆提案」。系统检查目标属于同一项目，更新事实、追加正文、建立关联或沉淀技能。通过任务 ID 避免重复应用。

## 落盘格式

- 笔记正文的演化区块写入 `append_insight`。建议关系以 `- [[uuid|标题]]` 追加到任务所在笔记。

  ```md
  <!-- plate-evolution -->
  第一轮补充说明
  <!-- /plate-evolution -->
  ```

- SQLite 的 `memory_evolution_logs` 保存 `delta_summary`、同次事实更新摘要、版本号和修订前片段，认知年轮从这里读取。替换事实时，`semantic_assertions` 保留旧断言，设置其 `valid_to` 和继任断言 ID，同时新增当前有效断言。
- 应用时，目标笔记有未保存草稿会阻止写入。通过检查的 Markdown 追加先记入 SQLite 待写入队列，落盘后确认。已入队但尚未落盘的写入可从「做梦整理」重试。
